# ADR-2604211639: ADR Format — Grandfather Existing Sections, Flag Review-Tool Mismatch

**Status:** Accepted
**Date:** 2026-04-21
**Drivers:** `hex adr review` reports 441 findings across 21 ADRs (0 PASS), most of them false positives from a format mismatch between three hex tools.

## Context

On 2026-04-21, `hex adr review` reported:

- **42 metadata findings** — every ADR flagged for missing `- **Date**: ...`, `- **Status**: ...`, `- **Authors**: ...` bullet-format header fields.
- **399 scope-conflict WARNINGs** — pairwise keyword-overlap warnings (e.g. ADR-001 ↔ ADR-003 share 8 keywords).

Investigation showed three hex tools expect three different ADR formats:

| Tool                  | Expected format for Status                                       |
|-----------------------|------------------------------------------------------------------|
| `hex adr list`        | `## Status\n<value>` — parses correctly (reads `accepted`/`proposed`) |
| `hex adr review`      | `- **Status**: <value>` — bullet line in the header block           |
| `hex adr schema`      | `**Status:** <value>` — bold-inline, plus YAML frontmatter fields  |

The 21 existing ADRs uniformly use the `## Status` / `## Date` section-header format. `hex adr list` parses them correctly; `hex adr review` does not. Zero of the 21 ADRs use the bullet format or the canonical bold-inline format.

The scope-conflict WARNINGs are generated by a keyword-overlap heuristic that fires on generic shared vocabulary (`adapters`, `diff`, `http`, `domain`) even when two ADRs make no overlapping decisions. The signal-to-noise ratio is poor for small ADR sets.

## Decision

1. **Grandfather the 21 existing ADRs in their current `## Status` / `## Date` section-header format.** Do not rewrite them to match the bullet or bold-inline format. `hex adr list` already reads them correctly; the review-tool regex is the wrong side of the mismatch.
2. **New ADRs from this one forward use the canonical format declared by `hex adr schema`**: bold-inline `**Status:**` / `**Date:**` / `**Drivers:**` header, plus the five required sections (Context, Decision, Consequences, Implementation, References). This ADR itself is the exemplar.
3. **Add a `## Authors` section to all 21 grandfathered ADRs** (done in the same commit as this ADR). Authors was the one field genuinely missing in every format.
4. **Accept scope-conflict WARNINGs as heuristic noise for now.** Do not edit ADR bodies to dodge keyword-overlap. If a pair represents a real decision overlap, add a targeted `## Related ADRs` section; otherwise ignore.
5. **File an upstream hex-intf issue** asking `hex adr review` and `hex adr schema` to agree on a single format (and for `hex adr schema` to emit a TEMPLATE.md — currently reports `⚠ TEMPLATE.md not found`).

## Consequences

- `hex adr review` will continue reporting ~42 metadata findings against the 21 grandfathered ADRs until the upstream tool is fixed. Those are known false positives and should not drive further churn in this repo.
- The 399 scope-conflict WARNINGs remain noise; they can be filtered out of future review runs.
- Future ADRs have a clean compliant template to follow (this file).
- Any tooling that keys off ADR status (e.g. `hex adr list`, swarm routing) continues to work because the `## Status` section parser still hits.
- If the upstream review regex ever changes to match the schema's bold-inline format, the 21 grandfathered ADRs will need a single mechanical migration pass. Cost deferred, not eliminated.

## Implementation

- Added `## Authors\nGary Berger` to all 21 existing ADRs (21 files, 63 insertions) in the same commit as this ADR.
- No other changes to grandfathered ADR bodies.
